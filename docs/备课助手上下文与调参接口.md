# 备课助手上下文与调参接口

日期：2026-11-09。目标：将系统提示词、阶段上下文、教材检索、学情证据和可调生成参数接成同一条备课流程。

## 教师入口与参数

打开「模型设置 → 高级：生成参数与上下文」，修改后点击「保存设置」。新任务使用新参数，正在执行的任务使用开始时保存的调试配置快照。

| 阶段 | 默认 temperature | 建议调试起点 | 默认最大输出 | 首次输入预算（估算 tokens） |
| --- | --- | --- | --- | --- |
| 教学设计 | 0.30 | 0.20—0.50 | 32768 | 64000 |
| 学情修订 | 0.20 | 0.10—0.30 | 32768 | 96000 |
| 视觉规划 | 0.50 | 0.40—0.70 | 16000 | 32000 |
| 教材识图 | 0.10 | 0—0.20 | 1500 | 图片与短描述单独发送 |

以上是工程调试起点，不是已验证的最佳教学参数。Temperature 可设0—2；输出上限可设512—32768。识图 top_p 可设0.01—1，默认1，通常先单独调整温度或 top_p。实际影响取决于所选模型服务。

当前 DSH 的 AgentOptions 不透传温度；本项目通过每个 teacher Agent 作用域内的 `agent/request` waterfall 设置 temperature 与 maxTokens，保留 provider/model 路由，并由 DSH 记录请求配置。当前 DSH pi-ai 文本通道没有 top_p 字段，因此文本阶段拒绝该参数，避免出现“设置了但不生效”的开关。识图接口直接传 temperature、top_p、max_tokens。

服务参数依据 [SiliconFlow Chat Completions 文档](https://docs.siliconflow.cn/docs/api/chat-completions-post)；文本通道能力同时核对了本机 DSH 的 AgentOptions、LlmCallConfig、agent/request 和 pi-ai 适配器实现。

## 上下文处理

1. 教师本次要求、修订时的完整原设计、教师选择和当前反馈是必要内容。预算不够时明确失败并提示提高预算，不静默截断这些内容。
2. 上传资料先检索相关段落，不再把全文直接塞进任务。教材使用词面 IDF 排序、相邻片段和精确去重，保留 source/knowledge 标识、chunk、偏移和可用的文件页序。未命中时明确标为 fallback_not_matched，不假称找到了教材依据。
3. 教材和资料去重只移除规范化后相同的文本，不合并只有数字、否定词或条件不同的内容。长无标点段落也会拆成有界片段。
4. 班级历史记录按本课相关性再按原有新旧顺序选择；每条检测补充题目内容、目标描述、知识点、课题/版本、时间、独立完成条件和记录依据。正确人数、总人数、未知和零保持原口径，不生成掌握率。
5. 视觉阶段保留固定标题、要点、页序与教学意图，完整讲稿在本地保留供导出。按页给出候选素材并控制目录总量；词面未命中时仅提供少量明确可追踪的回退候选，由模型判断是否使用。
6. 按阶段估算首次输入大小，对教材、资料、历史学情交错选择，避免单一长文占满上下文；context_manifest 明确省略范围。这里使用 UTF-8 字节数/2 的保守工程估算，不是模型的精确 tokenizer 计数，也不是后续所有工具对话的硬 token 上限。
7. 工具参数定义使用与后端同源的完整 JSON Schema。校验反馈只给字段路径、错误摘要、修复要求和剩余次数，不重复错误输入全文；达到失败上限后保留材料并停止本阶段。

主提示词加强了分层依据；新增 `prompts/context.md` 与 `prompts/quality.md`。质量清单要求在提交前检查目标—过程—检测、知识与答案、时间、学情适配和材料一致性。本次没有额外创建独立模型审稿调用，不能把自查清单当作事实已通过外部审阅。

## 调试 API

配置文件：`config/agent-tuning.json`。示例：`config/agent-tuning.example.json`。

- `GET /teacher/api/tuning`：返回 config、ranges、capabilities 和建议调试区间。
- `POST /teacher/api/tuning`：按阶段或字段部分更新配置，数值越界、未知字段和文本 top_p 返回400。沿用工作台 bootstrap 的 X-Teacher-Token 校验；不接收或返回模型密钥。
- `GET /teacher/api/context-report?job=<任务ID>`：返回该任务的参数快照、实际请求钩子应用记录，以及上下文预算、筛选/省略数量和来源标识；不返回教材原文或学生反馈全文。旧任务没有新增字段时返回空报告。

POST 请求体示例：

```json
{
  "stages": {
    "design": {"temperature": 0.3, "max_tokens": 32768, "input_budget_tokens": 64000},
    "revision": {"temperature": 0.2},
    "visual": {"temperature": 0.5},
    "vision": {"temperature": 0.1, "top_p": 1.0}
  },
  "context": {"retrieval_chars": 16000, "source_chars": 18000, "history_records": 8, "assets_per_page": 4, "max_assets": 32},
  "max_validation_attempts": 3
}
```

API 提供的是本机调试能力，不改变已有课程的设计、原图、交付文件或已生成图片的缓存。

## 使用边界

词面检索可能漏掉同义表达；上下文预算是工程估算。生成参数应结合实际课程调试，自查清单不代表外部教学质量评审。
