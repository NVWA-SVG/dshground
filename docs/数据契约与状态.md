# 数据契约与状态

可执行契约在 `backend/teacher_prep/models.py`，五类 JSON Schema 由 `SCHEMAS` 生成。业务接口可用 `schema` 命令查询，导入内容使用 Pydantic 校验。

## 关联关系

```text
课程请求 / 班级汇总学情
    → 教学版本
        → 教学目标 / 知识点
        → 教学环节 → 课件页面 → 页面逐字稿
        → 对应目标、知识点和环节的检测题
    → 实际授课版本的反馈 → 分项分析与建议
    → 教师选择 → 差异及依据 → 子版本
```

全局 ID 不重复；页面按环节顺序排列，每个环节有页面，每个目标有评价任务。新增知识点只能首次引入一次。导出可能对长内容自动拆页，因此教师文档的页码来自实际导出映射，不直接假设一条 Slide 数据就是最终一页。

## 持久化

SQLite 保存在实例根目录的 `data/teacher-prep.sqlite3`，包含 classes、lessons、versions、feedback、decisions、sources、export_jobs 和 ledger。正式实例与 `demo` 工程实例分开，避免将模拟学情混入教师真实课程。创建课程时分配班级标识；不同请求不按同名自动合并班级。复用已有班级时显式提供 class_id，并核对名称和年级。

版本设计只新增、不原地覆盖；状态为 draft、exporting、ready 或 failed。课程尚无版本时为 awaiting_design；等待反馈与等待教师选择由对应记录推导。业务操作使用事务及幂等键，单版本导出使用进程锁；Windows 进程检查只查询状态，不向进程发送信号。

导出先写任务临时目录、校验后发布。失败保留错误和工作区；重试使用同一个设计版本。交付目录若已存在只校验并复用，损坏时报告失败，不静默覆盖。

## 知识库与班级学情

`knowledge` 表保存教师知识库的元数据：名称、学科、年级、原文件名、哈希、字数、分段数。原文、抽取文本和 `chunks.json` 保存在 `data/knowledge/<id>/`。上传时按段落和句子切分；检索使用中文二元组和英文词的词面匹配，返回限定数量和总字数的相关段落，不调用嵌入模型。

`LessonRequest.knowledge_ids` 记录本课选择的知识库；`LessonDesign.knowledge_ids` 记录实际使用的知识库。生成时宿主把检索到的段落放入模型上下文，保存设计时校验教师选择的知识库都出现在设计中；修订不能移除原版使用的知识库。知识库被任一课程请求或版本设计引用时拒绝删除。

`class_profile` 由 `classes` 基线和该班所有课程的 `feedback` 聚合而成，返回最近 8 条反馈的原文摘要、观察、参与和检测结果。新备课与修订把它作为历史证据放入上下文；它不是能力评分，不自动推断掌握。`update_class` 只允许修改班级名称、年级、人数、已知学生情况和学习困难，不改变已生成版本。

## 课程整理

`LessonRequest.category` 是课程分类（0—40 字符），随 lesson payload 保存；旧数据缺省视为未分类。`update_lesson` 只接受白名单字段：课程名称、分类、班级名称始终可改；没有教学版本时还可修改课程类型、年级、学科、课时、班级人数、学情和授课要求。已有版本时其他字段必须通过学情修订生成新版本，避免已生成材料、页码和设计不一致。

`delete_lesson` 在一个事务中删除该课程的 decisions、feedback、export_jobs、versions（按版本号倒序）和 lesson；只被该课程使用的 class 与 sources 一并删除，共用资料保留。删除后移除该课 deliverables 目录、独占资料目录和版本锁；课件任务记录与 data/ppt-runs 由宿主清理。删除不可撤销，存在运行中任务时拒绝。

## 完成与验收

ready 表示实际文件已生成并通过程序校验，不表示 Office 版式、知识正确性、客户端集成或真实教学效果已经验收。交付清单分别保留 openxml_structure、office_visual_review、teaching_content_review 状态。

版本差异由程序比较得出，不能由模型自行声称已改动。change_links 必须逐项覆盖实际差异，依据必须来自教师已采纳的建议。下一阶段引入 LangGraph 时，检查点管理执行控制，SQLite 中的业务记录仍是课程事实依据。
